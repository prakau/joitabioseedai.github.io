# Release 1B: faster startup and dependable tool access

## 1. Existing foundation

This increment extends Release 1A in the audited existing React/Vite app. The
production backend already provides advisory, speech and market APIs. Device
records, checkpoint recovery, the product website and current URLs are retained.

## 2. Changes

- Load advisory, 3D, diary, calculators, ledger, sale planner, sound, field forms
  and recovery views on demand. Keep the dashboard and navigation available.
- Move answer-only Markdown rendering with the advisory view instead of loading
  its parser in the shared dashboard components.
- Startup JavaScript falls from 1,225,100 bytes to approximately 460,000 bytes,
  about 62% less uncompressed code; gzip falls from about 350 KB to 149 KB.
  These are build sizes, not a claim of measured page-speed or Core Web Vitals.
- Search all 14 dashboard tools using Hindi/English terms; clear search and display
  useful empty results. View three recent answers and reopen the selected saved
  response without another API call. Saved answers explicitly identify their age.
- Keep header/navigation when a view fails, with reload and dashboard recovery.
- Generate a complete, revisioned offline cache including all deferred chunks.
  Readiness requires a completion marker and the current entry file. Discard
  incomplete installations; preserve one previous build for already-open tabs.
- Website navigation closes on Escape/outside click and restores keyboard focus
  on Escape. Add keyboard skip links to both website and app.

## 3. Database changes

None. No record keys, schemas or IDs change. No cloud registry, enrollment,
consent, tenant access or synchronization is introduced. Cache Storage holds app
files only; deleting an obsolete app cache does not delete localStorage or
IndexedDB records. Current plus one previous offline build can occupy more disk
space than the earlier single cache.

## 5. Security and data integrity

No keys, permissions or public API behavior change. Offline caching is restricted
to same-origin app assets/navigation and excludes APIs. A saved answer is read
from the existing local collection, rendered as ordinary text/Markdown, and is
not resubmitted automatically. Recovery never clears records. Existing warnings
about device storage and backup remain applicable.

## 6. Environment

No new environment variables, secrets, service subscriptions or billing changes.
Vercel continues using its existing server-side provider configuration.

## 7. Verification

- Unit/API/data/stream suite: 65 cases.
- App browser suite: 47 cases, including bilingual search, saved Hindi answer
  reopening without a new request, failed chunk recovery, and deferred 3D loading.
- Website suite: six cases, including mobile menu behavior and the existing
  single-submit Hindi question handoff, product search and comparison.
- Cold offline browser test: first offline 3D visit renders nonblank geometry;
  advisory, calculators, ledger, diary, sales and saved answers survive reload.
- Interrupted asset download: no partial ready cache or false readiness; a later
  successful install restores offline tools. Unrelated caches are preserved.
- Production Vite/TypeScript build and Android-mode web bundle compile. This does
  not constitute a newly built, signed or device-tested Android APK.
- Mobile/tablet/desktop screenshots and overflow checks; reduced-motion controls.

Fixture-based browser tests establish software behavior, not the agronomic
accuracy of arbitrary provider answers. Production verification uses the real
public domain and is reported with the pushed commit and deployment result.

## 8. Deployment and rollback

Commit source and generated static assets together; push to the existing main
branch. The existing Vercel Git integration deploys them. Check the web regression
workflow and Vercel status, then verify health and a real Hindi crop answer.
Rollback can redeploy the preceding Vercel build. Do not manually remove stored
farmer records or unrelated browser caches. The worker rejects a root HTML file
that does not match its build entry during an overlapping deployment.

## 9. Remaining limits

Offline preparation still downloads all tool files in the background; a smaller
startup script is not a smaller total offline download. Live AI, weather, speech
and prices require connectivity. One previous build is retained; tabs older than
that may need a reload if they open an obsolete, uncached chunk.

The Three.js tool remains about 549 KB uncompressed and triggers Vite's chunk
warning, but is deferred from dashboard execution. Existing CSS build dependency
audit findings remain. Provider quota and per-instance rate limits are unchanged.
Detailed tools are not all translated. Secure cloud accounts, tenant isolation
and synchronization still require the existing PostgreSQL/identity integration.

## 10. Next increment
