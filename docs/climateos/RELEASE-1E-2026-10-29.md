# Release 1E: saved crop seasons and connected field checks

## Scope

Connect actual farmer records to existing advice and Calendar workflows. Retain
the public website, CNAME, Vercel host, server-only credentials and existing
records. This release makes no claim of superiority over another farming app or
of field-validated diagnosis, sensor monitoring or credit eligibility.

## Working farmer journey

- My Crops saves up to 30 field/crop-season records on the current device.
  Capture field name, crop, district/state, optional sowing date/area with units,
  observed stage, irrigation method and private notes. Edit, complete or reopen
  a season without deleting earlier records. Concurrent edits are rejected.
- The dashboard selects a field for new Ask/Diagnose questions. A single
  dashboard submission still starts advice immediately. The crop, reported
  stage and location prefill the request; bounded field facts provide sowing,
  area/unit, irrigation and plot context. Private notes never accompany advice.
- A question about another crop drops the selected field profile, old stage and
  unrelated conversation history. Saved answers and crop cases do not inherit
  today's active field. Follow-ups retain the original profile snapshot, not
  silently updated area or irrigation facts.
- Schedule a field/moisture check on an explicit date in the existing Calendar.
  A task cannot precede recorded sowing. Repeated clicks, including after task
  completion, do not duplicate the same field/date check. Calendar completion,
  dashboard tasks and existing ICS export continue to work. No background
  notification, chemical treatment or recommended application rate is invented.
- English/Hindi forms, summaries, navigation and tool discovery. Modest entry
  animation respects reduced motion. Dates after/before sowing are arithmetic,
  not automatic growth-stage predictions or sensor readings.

## Storage and safety

New records: `joita-fa-crop-seasons-v1`. Selection preference:
`joita-fa-active-season-v1` (excluded from record backups). The reader rejects
damaged, duplicate or over-limit collections; write failures do not claim success.
Existing calendar data is read and validated before new tasks are added, without
discarding historical records. Editing/completing a season does not rewrite
previous tasks or answers; farmers can review those in Calendar/history.

Exports containing seasons use backup version 6. Imports 3/4/5 remain supported,
including original IDs and case links. Version 6 supports validated merge,
conflict preservation and device recovery copies. Crop seasons, private notes
and prior field context are included in unencrypted farmer-record exports, so
those files must stay private. Raw recovery remains available for damaged data.

The API only adds an optional bounded `investigation.fieldProfile` context field.
Both providers receive it as unverified farmer-reported data, never instructions
or evidence of soil measurements, weather, yield, irrigation need or diagnosis.
Logs do not add raw profiles, private notes, documents or credentials.

## Verification

- TypeScript and production Vite build.
- 90 unit/API/data/stream tests; 64 app browser tests.
- Seven public-website browser regressions.
- Hindi layout at 360/768/1440 pixels and reduced-motion checks.
- Cold offline first use/reload of My Crops; save/select a season and create a
  Calendar task offline. Existing offline 3D pixel checks, saved Hindi answers,
  crop cases, calculators, sale comparisons and interrupted-download recovery.
- Android-mode bundle compilation/sync, not a new APK release.

Local mocks establish software behavior, not provider uptime or agronomic
accuracy. After push, verify the GitHub regression, Vercel commit deployment and
one real public Hindi advisory separately.

## Remaining limits

No connected cloud account/database/sync, staffed expert network, automatic IoT
feed or push service is introduced. Records remain device-local. The existing
published Android 1.0.3 test APK does not automatically receive these web changes.
The deferred Three.js bundle-size warning remains.

Data.gov.in returned `connection_failed` / `ECONNREFUSED` from the public market
endpoint on 29 October before this release. This is an external feed limitation;
manual buyer comparisons and actual dated caches remain available, not fabricated
prices or an unconnected alternate provider. Independent agronomic review and
farmer usability trials remain necessary before efficacy or superiority claims.
