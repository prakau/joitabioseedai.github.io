# Release 1A: calendar integrity and device recovery

This is an independently deployable **part of Release 1**, not completion of
JOITAFA 2.0 or ClimateOS. Secure authentication, tenant storage and cloud sync
remain blocked on integration with the user's existing PostgreSQL/identity
services. No new provider or large-scale migration was introduced.

## 1. Already existed

React/Vite PWA and Capacitor app; public Vercel advisory, speech and market APIs;
weather, image advisory, local diary, tasks, sale planner, ledger, calculators,
sound metrics, soil reports and 3D layouts. Existing IDs and localStorage keys
are unchanged. Prior homepage interaction work was unfinished in this checkout.

## 2. Added or changed

- Baseline audit, current/target architecture, proposed relational schema,
  privacy review, staged backlog and existing-backend integration checklist.
- Tasks before sowing require an explicitly supported pre-plant activity.
  Contradictory historical tasks show Needs review, not false overdue warnings.
  Date validation also applies to ICS export; records remain editable.
- Version 4 backups with version 3 compatibility, file-size/shape/unit/ID checks,
  allowlisted storage collections, duplicate detection and conflict preview.
  Merge adds new records only; current conflicting records are preserved.
- IndexedDB manual checkpoints and pre-restore/current-import checkpoints.
  Restore checks for changes after preview, attempts rollback on storage failure,
  reports incomplete recovery and is idempotent on repeated imports.
- Private raw export for review if existing records fail validation. Raw exports
  are not imported as trusted records. No data is silently converted to empty.
- English/Hindi recovery controls and explicit device-local/cloud-not-connected
  labels. AI backend connectivity is not represented as record synchronization.
- Completed pending homepage task finder, product filters/comparison and
  single-submit question handoff. Private question text is not put in the URL.
  Fixed the comparison bar being obscured by scroll-reveal stacking contexts.
- Source-map-js 1.2.1 -> 1.2.2 targeted transitive security patch.
- Automated GitHub web regression workflow on relevant pushes and PRs.

## 3. Database changes

No PostgreSQL migrations or production data changes. New device database:
`joitafa-recovery-v1`, object store `checkpoints`, keyed by UUID. Each checkpoint
contains a validated backup, reason and timestamp. Current working records
remain in localStorage; this is not a completed IndexedDB storage migration.
No contacts, registry enrollments, consent, tenant or impact records were created.

## 5. Security implications

Backup imports are treated as untrusted data. Unknown storage collections,
prototype keys, invalid units/shapes, repeated IDs and oversized files are
rejected. Merges cannot overwrite arbitrary localStorage preferences or keys.
Snapshots finish their IndexedDB transaction before the restore begins.
Files and checkpoints are not app-encrypted: protect them on shared devices.
Restored self-reported records are not independent evidence or verified results.

Remaining risks: process-local API limits, no accounts/tenant isolation/consent
service, localStorage cross-tab race windows, browser eviction, unfinished
translation, large Three.js bundle. CSS build dependencies retain npm audit
findings (5 high, 2 moderate after the targeted patch); fixing them through the
suggested Tailwind major upgrade needs a separate visual/build regression pass.
The API dependency audit reports zero known vulnerabilities. This is not a
penetration test or a claim of complete security.

## 8. Deploy and rollback

1. Run `npm ci --prefix api` and `npm ci --prefix farmassist-src`.
2. Run app tests/build and Playwright suites. The GitHub workflow repeats them
   against the built website using synthetic data; offline verification runs
   with network disabled after shell caching.
3. Commit source and generated `farmassist/` together and push main to the real
   origin. The existing Vercel Git integration builds and deploys the same repo.
4. Verify Vercel's successful deployment status, public homepage and app assets,
   `/api/health`, settings recovery and the calendar regression on the real domain.
5. Roll back by redeploying the previous Vercel deployment if needed. Local keys
   remain compatible; the additive `preplantActivity` field does not remove old
   fields. Retain exported backups and new IndexedDB checkpoints for recovery.

Do not overwrite CNAME, move hosting, delete local data, import outreach contacts
or apply unreviewed database DDL. Installed Android APKs are not updated by this
web release; build/test a new APK separately before announcing an Android update.

## 9. Known limits

- Checkpoints are manual or restore-triggered, not continuous backup. Clearing
  site data/uninstall can erase them. Download a private external backup.
- A browser/process interruption may leave part of a multi-collection merge
  applied. Re-import is idempotent; prior/import copies remain in IndexedDB.
  No cross-storage atomicity or cloud synchronization is claimed.
- Conflicting versions require comparison with the original backup; this release
  intentionally does not silently overwrite or automatically resolve conflicts.
- Backups omit profile settings, photos/audio and third-party caches. Legacy
  soil/EHI rows stay archival and must not enter validated impact reports.
- No Climate Passport, institution dashboard, carbon credits or payment workflow
  is released. No new farmer adoption/results/customer metrics are claimed.
