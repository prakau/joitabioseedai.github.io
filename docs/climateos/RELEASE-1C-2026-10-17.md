# Release 1C: connected crop care

## Scope

Build on the existing live React/Vite app, Vercel APIs and device-local records.
Keep the JOITA website, CNAME, public URLs, Android package ID and current data.
This is a practical follow-up workflow, not a claim of superiority to Plantix or
an independently validated disease classifier.

## Delivered behavior

- Guided diagnosis accepts up to three distinct farmer-labelled views: whole
  plant, leaf underside and field. Additional views are optional. Ask for symptom
  duration, distribution, plot and recent actions in the same submission.
- Gemini primary and OpenRouter fallback receive all supplied image bytes and
  context. Preserve old single-photo clients. Count analyzed views only on a
  successful provider response; offline knowledge never claims image analysis.
- Record or upload 1-30 seconds of speech, transcribe with the existing
  server-side Gemini key, review/edit the question, then submit once. Cancel,
  denied permission, late permission, timeout and provider failure are handled.
  Speech input does not automatically submit an unreviewed transcript.
- Save advice and observations as a crop case within Crop Diary, create a dated
  calendar recheck, add manual/photo follow-ups, and close/reopen the case. Pass
  saved advice plus up to three recent observations into a follow-up as
  unverified farmer context. Export reviewed records for an expert.
- Update the JOITAFA product entry and dedicated page with direct guided-check,
  Hindi-advice and crop-case links. Keep existing website navigation and pages.
- Android version 1.0.3-test, code 4, bundles the same features and retains the
  existing production backend and package ID. Release only after APK build and
  emulator verification; a web build alone is not an installable APK.

## Records and recovery

Extend `joita-fa-diary-v1` rows with optional `caseId`, root `caseInfo`, and
`advisory` snapshot. No migration, key rename, image/audio persistence, contact
import or automatic consent. Existing plain observations remain valid.

Case creation is idempotent by saved question ID. Partial calendar-write failure
preserves the saved case and offers retry without duplicating it. Follow-ups
must keep the root crop/plot and require an open case. Root deletion is disabled
while linked follow-ups exist. Closing a case does not mark it scientifically
verified or silently complete its remaining calendar tasks.

Backups containing case metadata export as version 5; other exports remain
version 4. Restore accepts 3/4/5 and validates links, identities, statuses and
bounded snapshots. Older builds reject 5 instead of dropping unfamiliar links.
Conflicting roots that would change a linked crop/plot reject before any write.
Corrupt current diary data is not replaced with an empty collection.

Before downgrading, export a private version 5 backup. An older app cannot safely
edit/restore the new linked cases. Clearing site storage or uninstalling Android
can erase local records; export before replacing a differently signed test APK.

## APIs, privacy and cost

New `/api/farmassist-transcribe` is POST-only with JSON responses, explicit
same-origin/native-origin CORS, MIME/header validation, a 2 MB decoded audio cap,
22-second timeout and instance-local 10 requests/IP/hour. It transcribes only;
unclear, malformed, truncated and overlength results are rejected. Audio and
transcript are not logged. Client recordings are capped at 30 seconds.

Health `hasVoiceInput` means a Gemini key exists, not guaranteed availability.
Photo requests have a combined 3 MB decoded cap and validated distinct view
labels. User-entered field notes are unverified context, not system instructions.
Existing advisory safety rules, language checks and honest fallback remain.

No new environment values, secret access, subscriptions, billing or quota changes.
Existing Gemini usage powers transcription; read-aloud still uses Google TTS.
These can consume paid provider quota. Photos/voice are forwarded to providers
only for the requested operation, not retained in app records. Provider retention
policies are separate; do not upload personal/private documents or audio.

## Remaining limits

Records remain device-local, not securely synchronized between web and Android.
The managed PostgreSQL/identity integration still requires its actual service
names and integration documentation. No invented expert queue, alerts, disease
accuracy score or verified recovery. Calendar export is not a background push
notification service. Some older detailed-tool labels remain English. Real
microphone hardware and farmer field validation still need device/user trials.
The deferred Three.js chunk retains the existing build-size warning. Rate limits
are per warm instance, not a distributed global quota.
